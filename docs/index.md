# AI-Augmented Software Development Lifecycle (AI-SDLC)

**Four-level process model inspired by C4: Landscape → Process → Specification → Playbook.**

AI-SDLC is a working framework for software delivery in which humans retain ownership of problem understanding, engineering decisions, acceptance criteria and production responsibility, while GenAI is used aggressively for execution, automation, documentation, analysis and other engineering toil where this improves delivery without weakening cognitive ownership.

## Navigation

* [**00 Principles & Governance**](00-principles/) — constitution of the model: human/AI ownership, decision rights, mandatory controls and governance rules.
* [**01 Level 1 – Development Landscape**](01-landscape/) — one-page executive/visual view of the lifecycle and relative Human/AI involvement.
* [**02 Level 2 – Development Process Map**](02-process-map/) — phase groups, major artifacts, owners, gates and risk-dependent flow.
* [**03 Level 3 – Process Specifications**](03-process-specifications/) — detailed specification of each lifecycle step: inputs, responsibilities, artifacts, exit criteria and risk adjustments.
* [**04 Level 4 – Engineering Playbooks**](04-playbooks/) — concrete technical instructions, checklists, agent instructions, prompts, skills and reusable implementation guidance.
* [**05 Risk Model R0–R4**](05-risk-model/) — cross-cutting risk classification controlling the strictness of gates, reviews, testing and release practices.
* [**06 Metrics & Evaluation**](06-metrics/) — delivery, quality and AI-specific metrics used to evaluate and evolve the framework.
* [**07 Change Log & Decision Records**](07-decisions/) — history of changes and important process/architecture decisions.

## Four levels of zoom

| Level | Main question | Primary audience |
| --- | --- | --- |
| **L1 Landscape** | How do we work with GenAI overall? | Everyone / leadership / onboarding |
| **L2 Process** | How does the whole delivery flow work? | Teams / leads / managers |
| **L3 Specification** | What exactly must happen in this step? | Owners of lifecycle steps |
| **L4 Playbook** | How exactly should a human or agent execute it? | Developers / QA / agents / automation |

The levels are **different zoom levels on the same lifecycle**, not sequential phases.

## Cross-cutting dimensions

The model is additionally governed by:

* **Human/AI Governance**
* **Risk Model R0–R4**
* **Metrics & Evaluation**
* **Decision Records / framework evolution**

## Current status

Working framework. Detailed content is being developed iteratively, starting with the constitutional baseline, the Development Landscape, Level 3 process contracts and executable Level 4 review/development playbooks.
