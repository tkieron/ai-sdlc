# 03.08 Implementation

> **Baseline v1.** Implementation may be substantially AI-executed, but remains human-owned and bounded by the approved implementation and correctness contracts.

## 1. Intent

### Purpose

The purpose of **Implementation** is to convert the approved implementation design into working source changes and test implementation while preserving the defined scope, contracts, invariants and correctness criteria.

AI may perform a large part of the execution, but MUST operate inside delegated boundaries and MUST escalate when execution would require a Material Decision or scope expansion.

### Scope

**IN SCOPE**

* implementation of approved source changes,
* implementation of approved automated tests,
* local refactoring required to complete the bounded task,
* mechanical mappings, boilerplate and configuration within scope,
* iterative compile/test/fix cycles,
* static and local quality checks,
* documentation updates directly required by the change,
* Agent Completion Report where delegated execution is material.

**OUT OF SCOPE**

* redefining functional intent,
* changing accepted test oracles without approval,
* expanding scope opportunistically,
* introducing material architecture/security/data decisions without authorization,
* unrelated refactoring or dependency upgrades.

### Inputs

Implementation SHOULD consume:

* approved Implementation Design,
* AI Implementation Contract where applicable,
* approved Test Intent / correctness contract,
* Definition of Done,
* applicable architecture and coding constraints,
* current risk classification.

### Entry Criteria

Implementation MAY start when **Ready for Development** is satisfied and:

* Material Decisions needed for execution are resolved,
* required permissions/tools are available,
* protected areas and stop conditions are understood,
* the responsible Human Owner understands the intended solution.

## 2. Responsibility & Authority

### Human Responsibilities

The Human Owner MUST:

* remain accountable for the implementation outcome,
* understand the design and delegated scope,
* decide material deviations or contract changes,
* review the resulting code before requesting external approval,
* confirm that AI did not silently expand scope,
* ensure material implementation risk is surfaced.

### AI Responsibilities / Permitted Role

AI MAY:

* implement source changes within scope,
* implement approved tests,
* execute build/test/static-analysis tools,
* iteratively repair implementation failures,
* make local, reversible implementation decisions permitted by the contract,
* propose additional improvements outside scope without executing them,
* produce an Agent Completion Report.

AI MUST NOT:

* modify accepted correctness criteria to make work pass,
* change protected contracts, schema, architecture, security or dependencies without authorization,
* continue beyond the delegated objective,
* hide material assumptions or deviations,
* claim completion when required validation has not passed.

### Decision Rights

| Material Decision | Human Authority |
| --- | --- |
| Scope extension | Human Owner / Lead |
| Change to contract or invariant | Appropriate Lead / Architect / Product owner |
| Change to accepted test oracle | Appropriate Human Correctness Owner |
| New dependency / security permission | Lead / Security / Platform as applicable |
| Acceptance of material deviation | Authorized Human Owner |
| Implementation completion | Author / Developer after required evidence |

## 3. Execution Contract

### Logical Activities

**Load Approved Context → Implement Bounded Change → Implement/Run Approved Tests → Compile / Static Checks → Iterate on Failures → Detect Deviations / New Material Decisions → Escalate if Needed → Complete Required Validation → Produce Agent Completion Report → Human Author Review Readiness**

### Required Artifacts

At exit, the following logical artifacts MUST exist:

* **Source Change**,
* **Required Automated Test Changes**,
* **Local Validation Evidence**,
* **Agent Completion Report** for material delegated execution.

### Mandatory Artifact Content

#### Source Change

MUST:

* implement the approved behavior,
* remain within scope,
* respect architecture/contracts/invariants,
* satisfy applicable coding and security standards,
* avoid unrelated changes unless explicitly authorized.

#### Agent Completion Report

For material AI execution SHOULD include:

* scope executed,
* files/components materially changed,
* validations performed and results,
* completion status against DoD,
* local implementation decisions made autonomously,
* deviations or unresolved issues,
* known risks,
* relevant work deliberately not performed,
* recommended follow-up work outside current scope.

## 4. Control

### Local Gate — Implementation Complete / Ready for Review

Implementation is complete when the bounded change satisfies its defined completion criteria and the Human Owner has enough evidence to begin formal review.

### Exit Criteria

The gate MUST confirm, proportionally to risk, that:

* the change compiles/builds,
* required unit/integration/local tests pass,
* accepted test intent has not been silently changed,
* required static/format/security checks have passed where applicable,
* no unexpected public-contract or architecture change is present,
* implementation remains within delegated scope,
* material deviations are visible and human-approved,
* Agent Completion Report is available where required,
* the author is prepared to review and explain the implementation.

### Required Evidence

Evidence SHOULD include:

* source diff/change set,
* test results,
* static-analysis / local quality results,
* Agent Completion Report,
* explicit record of approved deviations if any.

### Risk Adjustments R0–R4

* **R0:** MAY allow broad autonomous execution under existing patterns and lightweight completion evidence.
* **R1:** SHOULD use standard bounded execution and automated validation.
* **R2:** MUST preserve explicit scope, completion report and human review readiness; material deviations require approval.
* **R3:** MUST use tightly bounded agent scope, stronger independent checks and explicit lead review of deviations.
* **R4:** SHOULD be human-first with narrow AI support; critical implementation and irreversible operations MUST remain under direct human control.

### Stop / Escalation Conditions

The agent MUST stop and escalate when:

* required work crosses the approved scope,
* a Material Decision is discovered,
* architecture, security, schema or dependency changes are required,
* accepted tests and implementation behavior conflict,
* risk class materially increases,
* required validation cannot be completed,
* a protected artifact or environment must be modified.

Use **STOP → DESCRIBE → PROPOSE → ESCALATE**.

### Exceptions

Low-risk manual implementation MAY omit an Agent Completion Report. Emergency production work MAY compress normal implementation steps, but MUST preserve ownership, explicit intent, minimum validation and recovery considerations.
